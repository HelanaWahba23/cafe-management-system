# Café — Restaurant Management System

ASP.NET Core 8 / Blazor restaurant website with SQL Server, Entity Framework Core and Identity. Includes the customer menu and cart, delivery/pickup/table orders, customer accounts, cashier workspace, cash receipts, and admin catalog/table/report screens.

## Start from a fresh clone (Windows)

Install the **.NET 8 SDK** and **SQL Server Express LocalDB**. Visual Studio 2022 with the ASP.NET/web workload and LocalDB is also supported. A database, staff passwords, or User Secrets from the original developer are **not** included or required.

```powershell
git clone https://github.com/HelanaWahba23/cafe-management-system.git
cd cafe-management-system
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-local.ps1
dotnet run --project CafeManagement.Api --launch-profile https
```

The setup script restores/builds the app, applies all migrations to a **new dedicated database**, installs 27 demo dishes in six categories, creates an Admin with a randomly generated password, and configures the HTTPS development certificate. It prints your own admin credentials; save them privately. If the database name already exists, choose a new one:

```powershell
.\scripts\setup-local.ps1 -DatabaseName CafeManagementDemo2
```

For an installed SQL Server instance instead of LocalDB:

```powershell
.\scripts\setup-local.ps1 -Server '.\SQLEXPRESS' -DatabaseName CafeManagementDemo
```

This uses Windows authentication. Full manual setup and SQL authentication options are in [RUN-RESTAURANT.md](RUN-RESTAURANT.md).

Open **https://localhost:7128/**. In Visual Studio, open `CafeManagement.sln`, select `CafeManagement.Api`, choose the **https** profile and press F5. Run one server at a time; stop a terminal instance before starting Visual Studio.

**بداية التشغيل:** ثبّت .NET 8 SDK وSQL Server LocalDB، ثم شغّل `scripts/setup-local.ps1`. السكريبت ينشئ قاعدة تجريبية ومنيو وحساب أدمن خاص بك، ويعرض بيانات الدخول في النهاية. لا تستخدم بيانات حسابات المطوّر.

## Try the application

- `/menu`: 27 dishes, six categories, EGP prices, cart quantities, delivery or pickup checkout.
- `/customer/register`: create your own customer account; profile, saved address, and owner-only order history.
- `/account/login`: staff login using the Admin generated by setup.
- `/admin/tables`: create tables and open their QR menu links for dine-in orders.
- `/pos/orders`: staff order fulfillment and cash receipt workflow. Admin can also provision a separate Cashier; see the run guide.

Order progress is updated by staff. Guest checkout and private tracking links are supported. Payments are cash; no online payment provider, delivery service, GPS tracking, or email sender is configured. Archived Paymob work is historical and excluded from compilation.

## Configuration and verification

Private machine settings are in Git-ignored `CafeManagement.Api/appsettings.Local.json` or User Secrets. Never commit that file, passwords, database backups, or customer data. The local JSON fallback loads only in Development when no database connection is already configured; environment/User Secrets settings take precedence. It is excluded from build/publish output.

```powershell
dotnet tool restore
dotnet restore CafeManagement.sln
dotnet build CafeManagement.sln --configuration Release
dotnet ef migrations has-pending-model-changes --project CafeManagement.Api --configuration Release --no-build
```

GitHub Actions builds/publishes the project and checks migration consistency. See [setup and troubleshooting](RUN-RESTAURANT.md), [fresh-install validation](specs/007-restaurant-customer-site/publication-validation.md) and [feature validation evidence](specs/007-restaurant-customer-site/validation.md), and [implementation handoff](IMPLEMENTATION-HANDOFF.md). Historical validation results describe that recorded environment; they do not replace configuring a fresh database.
